- 마이페이지·프로필 수정·회원탈퇴에서 공통 로그인 확인과 회원번호 조회를 사용했습니다.
- 로그아웃과 탈퇴 성공 시 세션을 무효화하고 메인 화면으로 이동했습니다.

## 주요 처리 흐름

1. **JSP · JavaScript**: 중복 확인과 형식 검사 후 회원가입을 제출합니다.
2. **Controller**: 입력과 중복 여부를 서버에서 검증합니다.
3. **Model → JSP**: 실패하면 입력 DTO와 검증 결과를 회원가입 화면에 돌려줍니다.

아이디·닉네임·이메일은 다시 표시하고, 비밀번호는 비워두었습니다.

## 문제 해결 기록

### 반복되는 세션 처리를 LoginManager로 정리

**문제·상황:** 마이페이지, 프로필 수정, 회원탈퇴에서 세션의 로그인 사용자를 직접 읽고 회원번호를 꺼내는 코드가 반복됐습니다.

**처리:**

- LoginManager에 세션 저장·사용자 조회·로그인 확인·회원번호 조회 메서드를 만들었습니다.
- 각 Controller의 직접 세션 접근을 공통 메서드 호출로 바꿨습니다.
- 로그아웃과 회원탈퇴 성공 시 LoginManager.logout으로 세션을 무효화하고 메인으로 이동했습니다.

**변경 결과:** 여러 회원 기능이 같은 로그인 확인·회원번호 조회·로그아웃 처리를 사용하도록 정리했습니다.

**고려 사항:** 로그인 여부를 먼저 확인한 뒤 회원번호를 사용하도록 Controller의 처리 순서를 유지했습니다.

[근거](https://github.com/chlqjarb0216-bit/frade/pull/36)

변경 전:

```text
UserSessionDTO loginUser = (UserSessionDTO) session.getAttribute("loginUser");
int loginUserNumber = loginUser.getUserNum();
```

변경 후:

```text
int loginUserNumber = LoginManager.getLoginUserNum(session);
```

### 프로필 이미지 경로와 자산 표시 수정

**문제·상황:** 프로필 사진의 유무에 따른 이미지 선택과 경로를 수정하고, 자산·보유 종목의 숫자를 읽기 쉬운 형식으로 표시해야 했습니다.

**처리:**

- 프로필 사진이 있으면 저장된 이미지를, 없으면 기본 이미지를 표시하도록 분기했습니다.
- 프로필 화면과 수정 미리보기의 이미지 주소에 contextPath를 적용했습니다.
- 자산 금액·보유 수량에 천 단위 구분을 적용하고, 수익률과 비중은 소수점 두 자리로 표시했습니다.

**변경 결과:** 프로필 사진과 기본 이미지 분기를 수정하고, 마이페이지 금액·비율의 표시 형식을 통일했습니다.

**고려 사항:** 데이터 값은 그대로 두고 JSP의 출력 형식을 바꿨습니다. 금액과 비율에 맞는 형식을 각각 적용했습니다.

[근거](https://github.com/chlqjarb0216-bit/frade/pull/63)

변경 전:

```text
<h2>${assetsInfo.totalAsset}원</h2>
```

변경 후:

```text
<h2><fmt:formatNumber value="${assetsInfo.totalAsset}" pattern="#,###"/>원</h2>
```

### 회원정보가 없을 때 로그인 화면으로 이동

**문제·상황:** 마이페이지에서 회원정보를 조회했을 때 결과가 없는 경우에도 다음 이동 경로가 필요했습니다.

**처리:**

- 회원번호를 이용한 프로필 조회를 DAO와 Mapper에 연결했습니다.
- 마이페이지 처리에서 조회된 회원정보가 있는지 확인했습니다.
- 회원정보를 찾지 못한 경우 로그인 화면으로 이동하도록 분기했습니다.

**변경 결과:** 회원 조회 결과가 없는 경우 로그인 화면으로 이동하는 처리를 추가했습니다.

**고려 사항:** 마이페이지 진입 후의 조회 결과도 확인해 회원정보가 없는 상태를 처리했습니다.

[근거](https://github.com/chlqjarb0216-bit/frade/pull/45)

### 회원가입 검증 실패 시 입력값 유지

**문제·상황:** 회원가입 검증에 실패한 뒤 입력값이 사라지면, 사용자는 수정이 필요한 항목뿐 아니라 나머지 정보도 다시 작성해야 합니다.

**처리:**

- 서버에서 필수 입력의 빈 값, 아이디·닉네임·비밀번호의 공백, 비밀번호 확인 일치를 검사했습니다.
- 검증 결과와 입력 DTO를 Model에 담아 같은 회원가입 화면으로 반환했습니다.
- JSP에서 아이디·닉네임·이메일을 다시 표시하고 비밀번호 입력은 비워두었습니다.

**변경 결과:** 검증에 실패해도 비밀번호를 제외한 입력 내용을 유지하도록 구현했습니다.

**고려 사항:** 오류를 알리는 것과 사용자가 다음 시도를 이어갈 수 있도록 상태를 유지하는 것을 함께 고려했습니다.

[근거](https://github.com/chlqjarb0216-bit/frade/pull/5)

### 중복 확인과 최종 제출 검증

**문제·상황:** 입력 중 중복 여부를 확인하는 단계와 실제 회원가입을 제출하는 단계에 각각 검증이 필요했습니다.

**처리:**

- 아이디·닉네임·이메일 중복 확인 요청을 보내고 응답 코드에 따라 사용 가능 여부를 표시했습니다.
- 중복 확인 전에 공백과 이메일 형식을 검사하고, 제출 시 확인 완료 상태와 비밀번호 일치를 검사했습니다.
- 서버 회원가입 처리에서도 입력값과 중복 여부를 검증했습니다.

**변경 결과:** 입력 중 안내와 최종 제출 시 검증을 나누어 회원가입 흐름에 반영했습니다.

**고려 사항:** 브라우저에서의 확인만으로 서버 검증을 대신하지 않도록 두 단계를 구성했습니다.
